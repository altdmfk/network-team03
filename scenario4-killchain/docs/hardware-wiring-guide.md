# ESP32-C3 SuperMini 4색 LED + 부저 배선 가이드

디버깅하면서 확인된 사실만 반영한 최종 가이드. 이대로 처음부터 다시 꽂으면 됨.

## 1. 준비물

| 부품 | 수량 | 비고 |
|---|---|---|
| ESP32-C3 SuperMini | 1 | MicroPython 펌웨어 설치 완료 상태 |
| LED 5mm (파랑·초록·노랑·빨강) | 각 1개 | 긴 다리 = +(anode), 짧은 다리 = -(cathode) |
| 220Ω 저항 | 4개 | 색띠 무관, 전부 같은 값 |
| 액티브 부저 모듈 (SMG-A 계열, 3핀) | 1 | 핀 순서: **GND / VCC / S** (모듈 뒷면 각인 확인) |
| 브레드보드 (830point) | 1 | |
| 점퍼선 (수-수, Male-Male) | 최소 2개 | 부저 S용 1개, GND용 1개 |
| USB-C 데이터 케이블 | 1 | 충전전용 케이블 아닌 것 (데이터선 포함) |

## 2. 보드 핀 배치 (실측 확인됨)

USB-C 포트가 위를 향하게 놓았을 때 기준.

> **참고**: 보드 뒷면(스티커 면: `HW-466AB` / `ESP32-C3` / `SuperMini`)에서 보면 이 표의 좌/우가 반대로 보임 — 양면 인쇄라 뒤집으면 거울상이 됨. 아래 표는 **브레드보드에 실제로 꽂을 때(부품·USB·버튼이 있는 앞면이 위)** 기준.

**오른쪽 줄 (위 → 아래)**

| 순번 | 핀 | 용도 |
|---|---|---|
| 1 | 5V | 안 씀 |
| 2 | **GND** | → GND 점퍼선 |
| 3 | **3V3** | → 부저 VCC |
| 4 | **GPIO4** | → 부저 S |
| 5 | **GPIO3** | → 초록 LED |
| 6 | **GPIO2** | → 파랑 LED |
| 7 | GPIO1 | 안 씀 |
| 8 (맨 아래) | GPIO0 | 안 씀 |

**왼쪽 줄 (BOOT 버튼 라벨 아래 → "21" 있는 맨 아래)**

| 순번 | 핀 | 용도 |
|---|---|---|
| 1 | **GPIO5** | → 노랑 LED |
| 2 | **GPIO6** | → 빨강 LED |
| 3~7 | GPIO7,8,9,10,20 | 안 씀 |
| 8 (맨 아래, "21") | GPIO21 | 안 씀 |

> "BOOT", "PW", "RST"는 핀 번호가 아니라 그 옆 버튼 이름 라벨임 — 거긴 아무것도 안 꽂음.

## 3. 배선 순서

### 3-1. 보드 꽂기
브레드보드 중앙 홈에 걸치도록 그대로 꽂는다. (양쪽 핀이 서로 다른 세로줄에 들어감)

### 3-2. LED 4개 — 각각 독립적으로 (점퍼선 공유 금지)

4번 반복 (파랑=GPIO2, 초록=GPIO3, 노랑=GPIO5, 빨강=GPIO6):

1. LED **긴 다리(+)** 를 해당 GPIO 핀과 **같은 세로줄**, 몇 칸 아래에 직결 (점퍼선 없이 바로)
2. LED **짧은 다리(-)** 를 바로 옆 빈 세로줄에 꽂기
3. 저항 한쪽 다리를 LED 짧은 다리와 **같은 세로줄**에 꽂기
4. **저항 반대쪽 다리는 다른 저항과 공유하지 말고, 각자 GND 레일까지 바로 길게 걸쳐서 꽂기**
   - ⚠️ 저항 4개를 한 점퍼선으로 묶어서 GND로 보내면, 그 점퍼선 하나만 불량이어도 LED 4개가 전부 안 켜짐 (실제로 이 문제로 하루 종일 디버깅했음) — 반드시 저항마다 개별 연결

### 3-3. 부저 (3핀: GND / VCC / S)

| 부저 핀 | 연결 위치 |
|---|---|
| GND | GND 레일에 직접 |
| VCC | 점퍼선 1개로 보드 **3V3 핀**까지 |
| S | 점퍼선 1개로 보드 **GPIO4 핀**까지 |

### 3-4. 보드 GND → GND 레일

점퍼선 1개로 보드 **GND 핀 → 브레드보드 GND 레일(-)**. 이 선이 빠지면 전체 회로가 안 닫혀서 아무것도 안 켜짐 — 양 끝을 손으로 꾹 눌러 깊게 꽂을 것.

### 3-5. 큰 브레드보드 주의사항

830point 브레드보드는 보통 +/- 레일이 **중앙에서 끊겨있음**. 보드 GND 점퍼선과 각 저항의 GND 연결이 **끊긴 지점 기준으로 같은 쪽**에 있는지 반드시 확인. 다른 쪽이면 전기적으로 분리된 상태라 안 켜짐.

## 4. 연결 후 검증 (Thonny REPL)

main.py를 돌리기 전에, 핀 하나씩 직접 테스트해서 배선부터 확인.

```python
from machine import Pin
b = Pin(2, Pin.OUT)
g = Pin(3, Pin.OUT)
y = Pin(5, Pin.OUT)
r = Pin(6, Pin.OUT)
s = Pin(4, Pin.OUT)

# 전부 끄기 — 아무것도 안 켜져 있어야 정상
b.value(0); g.value(0); y.value(0); r.value(0); s.value(0)
```

```python
b.value(1)   # 파란불 확인
b.value(0)
g.value(1)   # 초록불 확인
g.value(0)
y.value(1)   # 노란불 확인
y.value(0)
r.value(1)   # 빨간불 확인
r.value(0)
```

4개 다 하나씩 정상 확인되면 main.py 실행(보드 리셋)해서 부팅(파랑)→Wi-Fi연결(초록) 시퀀스까지 확인.

## 5. 안 켜질 때 점검 순서 (실제로 겪은 순서대로)

1. **다른 LED로 교체** — 그 LED가 고장났을 수도 있음
2. **다른 저항으로 교체** — 저항이 타버렸을 수도 있음 (특히 한 번이라도 + 레일에 잘못 물린 적 있으면 의심)
3. **점퍼선 교체** — 선 내부 단선 가능성
4. **코드 없이 LED+저항을 3V3 핀에 직결** — 이러면 전원만으로 무조건 켜져야 함
   - 안 켜지면 → GND 레일 자체가 안 살아있는 것
5. **GND 레일 건너뛰고 저항을 보드 GND 핀에 직접(레일 안 거치고 핀↔핀)** 연결
   - 이러면 켜짐 → 레일이 범인, 앞으로 레일 대신 핀 직결 방식 사용
   - 이래도 안 켜짐 → 보드의 GND/3V3 핀 자체 손상 가능성, 멀티미터로 확인하거나 보드 교체 검토
